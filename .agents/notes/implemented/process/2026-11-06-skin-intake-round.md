# Agent Note: 2026-11-06 皮肤收录轮

Status: implemented

## Problem

2026-11-06 的皮肤收录轮需要对仓库当前开放的 7 个 PR（#77、#80、#83、#85、#93、#97、#99）按用户可见证据、第三方角色版权声明与多模态美学审查三道内容门禁逐项复核，裁定哪些 PR 已消除前序阻塞项可合并入 `main`，哪些 PR 因截图污染、契约越界或未提交更新而继续维持退回或阻塞状态，并明确市场试穿截图在准入校验中的口径以及大型资产包压缩后的实际打包边界。

## Decision

**合并入 `main`（`main` 依次推进至 `63572db5`、`abaa29d6`）：**

- **#83（`diy-journal` 体积压缩）：合并（`63572db5`）。** 用 `git tree` 逐文件求和核验：`skins/diy-journal` 由 `102,793,127` 字节降到 `39,389,604` 字节，减 `61.7%`，文件数不变（`485`）。组成：两个字体由 TTF 换成 WOFF2（`25,379,848 + 5,162,508` → `9,571,828 + 3,042,852`），`14` 个 SVG 的内嵌位图由 PNG 换成 WebP（有损 `q92`，尺寸与 alpha 不变），`7` 个 PNG 无损重编码；`patches.css` 两处 `@font-face` 已指向 `.woff2` 且带 `format("woff2")`，全目录无残留 `ttf` 引用；`skin.json` 版本由 `1.14.1` 升到 `1.14.2`。此前阻塞该 PR 的分支引用不一致（fork 分支指向 `cd8cf1a0` 而 PR head 是 `44eb3516`，`update-branch` 返回 `422`）已由作者修复。
- **#80（`md3`）：合并（`abaa29d6`）。** 上一轮退回的两处透字已修：`bg-layer-1..4` 与 `specific-input-major` 改为不透明实色（亮 `#f7f2fa`/`#f3edf7`/`#ece6f0`/`#e6e0e9`，暗 `#1d1b20`/`#211f26`/`#2b2930`/`#36343b`），不再用 `calc(0.96 + var(--dsw-skin-scrim) * 0.04)` 这种默认仍留约 `4%` 透明的写法；输入区改为在 `[data-composer-dock]` 内把画布令牌就地换成实色，不再依赖被皮肤中心 `backdrop-scene.ts:251-256` 用 `!important` 置空的 `[data-composer-seat]`。`README.md` 第 `81` 行「无背景图、无动画」与同文件 `78-80` 行 `20` 秒底板视频循环的自相矛盾已清理，第 `17` 行暗色 `error` 色值同步为 `#ffd6d2`。
- **关键判断：市场试穿截图不作为合入门槛。** 仓库自带的 `scripts/verify-evidence.mjs` 与 `.github/pull_request_template.md` 只要求「每个主题一张」（亮/暗），并把同字节文件提交进 diff，没有把 `dsh-market.com` 的试穿截图列为校验项。因此本轮按仓库既有标准执行，把市场试穿记为后续可选补充，以避免同一轮内对不同贡献者使用不同门槛。

**继续退回与维持阻塞：**

- **#77（`whale-watercolour`）：再次退回。** 会话态截图同时充当商店封面 `preview/{light,dark}.jpg`，画面仍混入 `dsh-pet` 桌宠浮窗压住回复正文与底栏，且截图时会话态背景高斯模糊开着、两侧画面列被糊平看不出局部 scrim 边界；`README.zh.md:120` 记录的 preview sha256 仍是旧值（实际 `9592b85b…`，`light` 与 `dark` 逐字节相同这点成立）。

- **#93、#97、#99**：维持既有 `CHANGES_REQUESTED`，作者未更新。

## Alternatives considered

- **以未解除市场打包体积上限为由，将 #83 判为未达成目标并退回。** 否决：#83 的声明目标即「减少体积 62%」，经逐文件核验实际缩减 `61.7%`（由 `102,793,127` 字节降至 `39,389,604` 字节），属于明确的净改善，字体转 WOFF2 与位图重编码方向合理，已兑现该 PR 自身承诺的范围；超出 `25 MiB` 市场打包上限的问题应作为后续独立缩体工作跟进，不应阻断已完成的压缩成果落地。
- **要求 #80 补交 `dsh-market.com` 市场试穿截图后再予合并。** 否决：仓库自身的证据校验脚本 `scripts/verify-evidence.mjs` 与 PR 模板 `.github/pull_request_template.md` 均仅要求提供亮/暗两态宿主实测截图并将同字节文件纳入提交，并未将市场试穿页截图设为准入条件；且前序批次中的 #101 与 #84 已按同一套仓库标准核准合入，若对 #80 临时附加模板外的试穿截图要求，会导致同一收录周期内评审口径不一致。

## Consequences

- 合并后 `dsh-skins` 的 `main` 推进到 `abaa29d6`，但卫星仓合并本身不上架；还需在 `dsh-web` 移动 `satellites/dsh-skins` 的 gitlink 并重建 `market/dist`。
- #83 并未解除 `25 MiB` 上限：市场 zip 用 store 方式（不压缩）打包，按同一口径算 #83 后仍是 `39,462,298` 字节（`37.63 MiB`），超过 `26,214,400` 字节上限 `50.5%`，`diy-journal` 依旧不产出 zip。要真正产出需再砍 `13.2 MB`，最直接的路径是把两个 CJK WOFF2（合计 `12.6 MB`）按实际用字子集化。
